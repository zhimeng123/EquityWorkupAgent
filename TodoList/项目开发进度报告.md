## 6. 后续开发建议顺序

### 第一阶段：清理和确认当前基线

目标：

把当前可用成果固定下来，避免后续开发覆盖已验证的 `result.docx`。

建议动作：

1. 复制或备份最新输出目录。
2. 确认 `result.docx` 是当前交付基线。
3. 运行现有测试，确认基础回归通过。
4. 不要重跑完整 Agent 来覆盖当前报告，除非明确要刷新全链结果。

### 第二阶段：逐字段消除报告占位内容

目标：

解决 result 中仍存在的未生成字段。

建议动作：

1. 建立字段清单：字段名、报告位置、对应 Agent 节点、对应数据源、当前失败原因。
2. 对每个字段选择根本方案：
   - 已下载年报可确定解析：走离线确定性解析。
   - 必须实时查询：走 Agent 工具链。
   - 当前 MVP 不纳入：明确保留为 MVP 未覆盖。
3. 每修复一组字段后，只针对该组做最小链路验证。

### 第三阶段：修复 Part08 行情源

目标：

让历史行情 / 市值 / 股价相关字段稳定产出。

建议动作：

1. 先复现当前失败。
2. 定位是否为网络、接口参数、反爬、返回结构变化。
3. 如果东方财富不可稳定使用，向业务确认是否切换到腾讯或其他源。
4. 确认后实现单一稳定源，不做多源 fallback。

### 第四阶段：完整 Agent 回归

目标：

确认从数据抓取、字段抽取、证据聚合、报告生成到渲染检查全链路可跑通。

建议动作：

1. 跑完整 Agent。
2. 对比新旧 `sources.json` 成功/失败数量。
3. 生成新的 `result.docx`。
4. 渲染检查 Word/PDF 页面。
5. 检查是否引入文字空洞、表格溢出或字段倒退。
