# 第 5 部分：关联交易与同行比较开发计划

## 前置依赖

必须等待第 4 部分的标准财务期间接口完成。同行结果同时是第 8、9 部分的前置输入。

## 目的

提取关联交易，并从显式业务配置读取三家同行，填充模板中的嵌套同行表和证据化结论。

## 已确定的同行规则

当前 MVP 从 `configs/fixed_peers.yaml` 按目标股票代码严格读取恰好三家同行。`000938` 固定使用神州数码（000034.SZ）、浪潮信息（000977.SZ）、中科曙光（603019.SH），配置同时记录选择理由。未配置目标公司时返回 `fixed peer configuration missing`，不调用全市场接口、不回退或自动补足。后续 MVP 再恢复全市场自动筛选。

## 要实现的字段

- `related_party_transactions`；
- `peer_comparison_table`；
- `peer_alignment_comment`。

同行表每家公司填写同一年度 Revenue、东方财富已披露的 Inventory Turnover、Gross Margin、Net Margin。Net Margin 固定为归母净利润 / 营业收入。

## 开发内容

1. 从最新年报和半年报提取关联方、交易类型、金额、商业条款和董事会审批情况；未披露审批结论时写 `Not disclosed`。
2. 加载并校验固定同行配置；运行时只为配置中的三家公司抓取真实财务和行情数据。
3. 同行财务数据不得由 LLM 生成；期间不一致的候选直接剔除。
4. 填写 `T7[1,0]/T0` 嵌套表，保留表头和 Proposer/peer 行结构。
5. 英文结论基于目标与三家同行的两年收入增长和最新年度毛利率、净利率；不得根据行业常识追加风险。
6. 同行分析与关联交易抽取使用两个独立失败边界：同行成功而关联交易失败时，Part 05 标记为 `partial`，保留三家 `selected_identities`、同行表和结论；仅将 `related_party_transactions` 标记失败，不伪造 `Not disclosed`。
7. 执行计划将 `partial` 视为节点已完成并在 `detail` 记录失败子域；只有同行选择或同行财务分析失败才将 Part 05 标记为 `failed`。

## 文件与接口

建议新增 `mlc_agent/peer_analysis.py`、`mlc_agent/related_parties.py`、`configs/fields/part_05.yaml` 及对应测试。输出选中同行的公司标识、两年财务记录和证据 URL，供第 8、9 部分直接使用。

## 测试与完成标准

- 固定同行配置必须恰好三家且股票代码不得重复；
- 未配置目标公司时明确失败且不得触发网络抓取；
- 关联交易多项格式；
- 嵌套表格每个目标单元格正确写入；
- 每家公司每个指标均可追溯到 URL 和期间。
- 覆盖“同行成功+关联交易超时”、“同行失败”和“两个子域全成功”三种集成测试。
